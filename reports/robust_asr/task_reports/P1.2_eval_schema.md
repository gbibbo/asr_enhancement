## Leakage tests (Section 3 leakage guard)

`tests/robust_asr/test_leakage.py` implements the five named tests
required by Section 3:

1. `test_speaker_disjoint_lora_vs_router_train` — operates on the
   real `data_v1.yaml` partition (lora_train=200 vs router_train=51,
   speaker-disjoint by construction; PASS).
2. `test_audio_id_disjoint_lora_train_vs_router_targets` — uses
   placeholder audio_ids derived from each speaker set (real
   manifests at P1.3); PASS by construction since speaker sets are
   disjoint.
3. `test_locked_test_sets_disjoint_from_train` — operates on the
   real partition (locked_test=40 test-clean speakers vs
   train=251 train-clean-100 speakers). PASS (LibriSpeech subset
   speaker domains are corpus-level disjoint).
4. `test_demo_examples_disjoint_from_eval_sets` — demo set is
   currently empty (BLOCKED_OOD_PUBLIC); writes
   `SKIP_OOD_PUBLIC_DEFERRED` note to
   `reports/robust_asr/leakage/test_demo_examples_disjoint_from_eval_sets.note.txt`
   and asserts trivial disjointness; PASS.
5. `test_common_voice_demo_disjoint_from_ood_locked` — both splits
   empty (BLOCKED_OOD_PUBLIC); writes
   `SKIP_OOD_PUBLIC_DEFERRED` note and asserts trivial disjointness;
   PASS.

On any failure, the intersection is written to
`reports/robust_asr/leakage/<test_name>.failure.txt` with one
intersecting ID per line, then `pytest.fail` is raised with a sample
of the intersection.
