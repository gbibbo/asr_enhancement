## 1. Issue fixed

The previous strict validator
(`scripts/robust_asr/verify_handoff_package.py`, assertion A7)
constructed the expected handoff tag from current HEAD:

```text
tag = "handoff/$(date -u +%Y%m%d)-$(git rev-parse --short HEAD)"
```

This made `--strict` fail at every HEAD after the P9.1 package
commit, even when the canonical handoff tag was valid and
unchanged. Specifically, the previous behavior emitted:

- at HEAD `9f54b028…` (pre-P9.2):
  `A7 FAIL: local tag missing: handoff/20260514-9f54b02`
- at HEAD `f900d808…` (post-P9.2):
  `A7 FAIL: local tag missing: handoff/20260514-f900d80`

Both failures were pre-existing tag-commit-drift artifacts;
neither was caused by P9.2's payload (the canonical tag
`handoff/20260514-64eba43` was on origin and unchanged in both
cases).

## 2. Fix

Strict assertion A7 now validates the **canonical handoff tag
recorded by the handoff package**, not current HEAD. Resolution
order:

1. Scan handoff `README.md` §7 Provenance for a concrete
   `handoff/<YYYYMMDD>-<hex>` tag string. The README's placeholder
   `handoff/<YYYYMMDD>-<short_sha>` is rejected by
   `HANDOFF_TAG_RE = re.compile(r"\bhandoff/\d{8}-[0-9a-f]{7,40}\b")`
   because the placeholder contains `<` and non-hex characters.
   §7 is extracted by scanning from `## 7. Provenance` to the next
   top-level `## ` heading; this scoping prevents the validator
   from accidentally picking up the example tag
   `handoff/20260101-abcd123` that appears in README §5.2 (rollback
   usage example).
2. Fall back to enumerating local `refs/tags/handoff/*` via
   `git tag --list 'handoff/*'`; if exactly one concrete handoff
   tag exists in the repo, use it as canonical.
3. As a last resort, if §7 contains multiple concrete tags AND the
   git tag list has multiple, use the intersection if it is unique
   (`readme_git_intersect`).
4. Otherwise emit a deterministic A7 failure without using HEAD.

The previous HEAD-derived construction is no longer attempted. A7
also verifies that the resolved canonical tag points to the same
commit locally and on origin.

A1 through A6 behavior is unchanged. A6 secret scanning is not
weakened. The non-strict mode emits `OK_HANDOFF_PACKAGE` as before.
The success sentinel remains `OK_HANDOFF_PACKAGE`. The failure
sentinel remains `FAIL_HANDOFF_PACKAGE: <ids>`.
